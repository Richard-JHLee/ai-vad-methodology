# RFC 0002: VAD v0.2 Evidence Model

- Status: Draft
- Version: 0.2 (proposal; core remains 0.1 until this RFC is accepted)
- Author: Richard J. H. Lee
- Created: 2026-08-15
- Relates to: [RFC 0001](./0001-vad-core.md)

## Summary

This RFC adds five evidence concepts to VAD without changing the six core properties, the seven workflow stages, or the five required artifacts:

1. Requirement Ambiguity / Clarification
2. Instruction Provenance
3. Agent Execution Evidence
4. Verification Cost
5. Performance Evidence

They are fields attached to existing stages and templates, scaled by risk.

## Motivation

RFC 0001 already requires that a change can be explained, verified, and recovered. In AI-assisted work, gaps still appear:

- Ambiguous requirements are implemented at high speed.
- The instruction that produced the patch is not recorded.
- Agent tool use is invisible after the fact.
- Teams either over-document low-risk work or under-prove high-risk work.
- Performance is ticked as done without a baseline or source.

## Non-goals

- Do not add a seventh core property alongside Understandable, Traceable, Verifiable, Limited, Recoverable, and Accountable.
- Do not add an eighth workflow stage.
- Do not add a sixth *required* artifact. Optional rows in existing templates are enough.
- Do not rewrite RFC 0001.

## Proposal

| Concept | Stage | Artifact fields |
|---|---|---|
| Requirement Ambiguity / Clarification | 1 Requirement Definition | Requirement Contract |
| Instruction Provenance | 4 Controlled Code Generation, 5 Change Mapping | Change Map |
| Agent Execution Evidence | 4 and 6 | Verification Report (and provenance on Change Map) |
| Verification Cost | 6 Automated and Human Verification | Verification Report; depth in risk levels |
| Performance Evidence | 6.4 Operational verification | Verification Report |

### Requirement Ambiguity / Clarification

Record open questions, answers, remaining unknowns, and whether generation is blocked. Unresolved blocking ambiguity is a stop condition.

### Instruction Provenance

Record the origin of the instruction (issue, chat prompt, agent task, human amendment), the human approver, and a prompt or task identifier with secrets removed.

### Agent Execution Evidence

When an agent executed the change, retain a trace of steps, tools, targets, results, and stop or error events. The trace is a verification *input*, not a verification *result*.

### Verification Cost

Record effort, tools, and coverage, and whether that cost is justified by risk. Wasteful ceremony on low-risk work is not VAD. Thin evidence on high-risk work is the defect.

### Performance Evidence

When performance, capacity, or infrastructure cost is in scope, record metric, baseline, after value, environment, and source. A checkbox is not evidence.

### Risk gating

| Evidence | Low | Medium | High / Critical |
|---|---|---|---|
| Ambiguity / clarification | Optional one-liner | If AI-assisted | Required; blocking questions resolved |
| Instruction provenance | Optional | If AI-assisted | Required |
| Agent execution evidence | If an agent ran | If an agent ran | Required if an agent ran |
| Verification cost | Skip or one line | Brief | Required |
| Performance evidence | Only if in scope | If in scope | Required when performance/cost/capacity is in scope |

## Alternatives

- New workflow stage 8 (Evidence Pack): rejected; dilutes the seven-stage model.
- Sixth required artifact: rejected; duplicates Verification Report and Change Map.
- Seventh core property such as “Economical”: rejected; cost is a risk control, not a new quality aim.

## Risks

- Template bloat and checklist theater.
- Recording prompts that contain secrets.
- Treating agent logs as proof of correctness.

Mitigations: risk gating, no-secrets rule, explicit “inputs not results” language.

## Migration impact

Additive. Existing 0.1 artifacts remain valid. Teams may ignore new rows on historical changes. Version stays Draft 0.1 until this RFC is accepted.

## Open questions

- How much of an agent trace must be retained, and for how long?
- Should verification cost use hours, story points, or a qualitative scale?
- Which performance metrics are minimum for API vs batch vs mobile clients?
- Can CI attach these evidence blocks automatically?
