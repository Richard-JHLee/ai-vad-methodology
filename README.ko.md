# VAD — 검증 가능한 AI 개발 방법론

> AI를 활용해 개발하더라도 소프트웨어가 사람에게 이해 가능하고, 추적 가능하며, 검증 가능하고, 복구 가능한 상태를 유지하도록 제안하는 공개 개발 방법론입니다.

## 왜 VAD가 필요한가?

AI는 개발자가 코드를 분석하는 속도보다 더 빠르게 코드를 생성할 수 있습니다.

이로 인해 소프트웨어 개발에는 새로운 문제가 발생하고 있습니다.

이제 가장 큰 위험은 AI가 정상적으로 작동하는 코드를 만들지 못하는 것이 아닙니다.

오히려 AI가 겉으로는 잘 작동하는 코드를 빠르게 만들어내는 동안, 개발자가 다음 질문에 답하기 어려워지는 것이 더 큰 문제입니다.

* 이 코드는 왜 변경되었는가?
* 시스템의 어느 부분에 영향을 주는가?
* 어디에서 문제가 발생할 수 있는가?
* 장애가 발생하면 어떻게 복구할 것인가?
* 누가 이 변경을 검토하고 승인했는가?

기존의 소프트웨어 개발 원칙은 여전히 중요합니다.

그러나 AI 보조 개발은 코드가 만들어지는 속도와 변경 규모를 크게 증가시킵니다. 기존 방식만으로는 인간의 이해와 검토가 AI의 생성 속도를 따라가기 어려울 수 있습니다.

VAD는 다음 기준을 중심으로 개발 절차를 제안합니다.

> 개발자가 변경 목적, 영향 범위, 실패 지점, 검증 근거와 복구 방법을 설명할 수 있을 때 비로소 소프트웨어 변경이 완료된 것으로 본다.

## VAD란 무엇인가?

**VAD**는 **Verifiable AI Development**의 약자입니다.

한국어로는 **검증 가능한 AI 개발**을 의미합니다.

VAD는 AI 코딩 도구나 자율형 AI 에이전트가 생성한 소프트웨어 변경을 사람이 통제하고 검토하며 안전하게 운영하기 위해 제안하는 개발 방법론입니다.

VAD는 AI 사용을 제한하거나 금지하기 위한 방법론이 아닙니다.

AI가 만든 결과물이 다음 조건을 유지하도록 만드는 것이 목적입니다.

* **이해 가능성**: 사람이 시스템의 동작과 변경 이유를 설명할 수 있어야 합니다.
* **추적 가능성**: 요구사항, 설계 결정, 코드 변경을 서로 연결할 수 있어야 합니다.
* **검증 가능성**: 테스트와 분석 결과를 통해 변경의 적합성을 확인할 수 있어야 합니다.
* **범위 제한성**: 사람이 검토할 수 있는 수준으로 변경 범위가 관리되어야 합니다.
* **복구 가능성**: 문제가 발생하면 변경을 중단하거나 이전 상태로 되돌릴 수 있어야 합니다.
* **책임 명확성**: 최종 승인과 운영 책임은 명확한 사람에게 있어야 합니다.

v0.2는 새 단계나 원칙을 추가하지 않습니다. 기존 생애주기에 걸쳐 요구되는 증거를 확장하여 AI 보조 변경을 더 점검 가능하게 만듭니다. 기존 세 속성을 두껍게 읽습니다. [RFC 0002](./rfcs/0002-vad-v0.2-evidence-model.md)를 참고하십시오.

* **추적 가능성** — 변경 출처, 지시 출처, 에이전트 실행 증거.
* **검증 가능성** — 정확성, 보안, 회귀, 운영 근거(성능 및 운영 비용 포함), 검증 비용(과정 지표).
* **책임 명확성** — 사람 승인, 실행 소유, 롤백 소유.
